## 1. 專案背景與研究動機

### 1.1 核心假設

主持人（湘敏）在實務觀察中發現以下脈絡：

- 虐待動物與公共危險／傷害案件，經常**前後或同時發生**
- 這類行為人後續可能出現更嚴重犯行：毒品、搶奪、竊盜、殺人等
- 相關的量化分析目前**幾乎只有美國有**，台灣沒有公開的同類數據分析

### 1.2 實務佐證

- 社工使用的危險係數評量表，已加入「是否涉嫌虐殺動物」欄位
- 家庭暴力通報中約 1% 涉及動物虐殺；以每年約 20 萬筆通報估算，約有 2,000 件
- 但這些案件幾乎都**沒有進入動保體系**，形成每年持續累積的黑數

> ⚠️ 待確認：上述 1% / 2,000 件的數字原始出處為何（衛福部年報？家防中心統計？），
> 以及是否能取得更細顆粒度（縣市別、年度別、動物種類）。
> 這類統計多為彙總數字，**無法做個案串接**，僅能用於總體對照。

### 1.3 專案目標

透過資料分析驗證並呈現此現象，使未來「同一行為人同時具備某罪行 + 虐待動物紀錄」時，
能夠**提前預警**。

## 2. 研究設計上的重大決定（必讀）

以下兩點是規劃過程中發現的結構性限制，會決定整個專案能回答什麼問題，
**請勿在實作階段跳過**。

### 2.1 跨判決的人物串接做不到

公開裁判書的被告姓名是**遮蔽**的（例：王○明）。
在全國數百萬筆的規模下，靠遮蔽姓名做 entity matching，同名碰撞會多到無法使用。
這不是演算法調參能解決的問題，是資訊本身不存在。

**→ 因此不建立跨判決的 Person Graph。**

### 2.2 改用「判決書內前科抽取」

刑事判決書通常會在事實或理由段落敘明被告前科，例如：

> 「曾因竊盜案件，經○○地方法院判處有期徒刑○月確定，於民國○年○月○日執行完畢」

累犯認定、量刑審酌、刑案資料查註紀錄表引用處都會出現這類敘述。
等於**每一份判決書自己就攜帶該被告的犯罪史**，可從單一文件抽取時序，
完全不需要跨文件比對人物。

**資料結構影響：**

- 分析單位 = 「判決內的犯罪序列」，而非「跨判決的人物時間軸」
- 每份判決抽出：本案犯行 + 前案清單（罪名、時間、法院、執行完畢日）
- 後案追蹤（虐待動物之後又犯了什麼）較弱，需靠後續判決提到動保前科來反向索引

### 2.3 研究問題方向要從「前瞻」改成「回溯」

| 方向 | 問法 | 資料可行性 |
|---|---|---|
| 前瞻 | 虐待動物者，之後有多少比例犯下暴力犯罪？ | ❌ 很難，需跨判決追蹤同一人 |
| 回溯 | 已犯下暴力犯罪者，回溯有多少比例有虐待動物史？ | ✅ 可行，前科敘述就在判決書內 |

回溯方向足以支撐預警訴求，且正好對應社工危險評估表的實際使用情境。

## 3. 資料來源（已查證）

### 3.1 結論：主要走官方開放資料，不是爬蟲

司法院已將裁判書做成正式開放資料，**按月打包 + API**，
收錄範圍與司法院網站的裁判書查詢系統相同。爬蟲僅在補洞時才需要。

### 3.2 管道一：按月打包下載（歷史資料主力）

- 平台：https://opendata.judicial.gov.tw/
- 資料屬「**會員開放資料**」，免費但需註冊帳號才能取得
- 需遵守《司法院開放資料使用規範》
  https://legal.judicial.gov.tw/FLAW/dat02.aspx?lsid=FL095666
- 資料依**月份、法院**分類，每份裁判書為一個獨立 JSON 檔

JSON 結構範例：

```json
{
  "JID": "SJEM,104,重秩聲,17,20160126,1",
  "JYEAR": "104",
  "JCASE": "重秩聲",
  "JNO": "17",
  "JDATE": "20160126",
  "JTITLE": "違反社會秩序維護法",
  "JFULL": "臺灣新北地方法院三重簡易庭裁定 104年度重秩聲字第17號..."
}
```

**JID 組成**：法院別 + 裁判類別, 年度, 字別, 號次, 裁判日期, 檢查單號
**裁判類別代碼**：民事 `V`、刑事 `M`、行政 `A`、懲戒 `P`、憲法 `C`
→ 刑事只取 `M` 開頭即可初步過濾

### 3.3 管道二：裁判書 API（增量更新用）

規格文件：https://opendata.judicial.gov.tw/api/Newses/42/file （114.08.22 版）

| 端點 | 路徑 | 說明 |
|---|---|---|
| 驗證 | `POST https://data.judicial.gov.tw/jdg/api/Auth` | 帶 user / password，回傳 Token（有效 6 小時） |
| 異動清單 | `POST https://data.judicial.gov.tw/jdg/api/JList` | 帶 token，回傳「7 日前」的異動 jid 清單 |
| 取全文 | `POST https://data.judicial.gov.tw/jdg/api/JDoc` | 帶 token + jid，回傳單筆裁判書 |

**關鍵限制：**

1. 異動清單只提供 **7 日前** 的異動，**無法回溯查詢歷史資料**
2. 服務時間限定 **每日凌晨 0 時至 6 時**，其餘時間不提供服務
3. 取全文需逐筆帶 jid，**無批次介面**

→ API 只能做「每天／每週追新」，歷史資料一律走月打包檔。
→ 排程程式必須設計成夜間執行、可中斷續傳。

### 3.4 管道三：爬蟲（僅在必要時）

- 司法院法學資料檢索系統 https://lawsearch.judicial.gov.tw/
- 僅在**老年份打包檔不存在**時才需要
- 已知第三方經驗：該系統會觸發防火牆（F5 WAF），需以瀏覽器模擬刷 cookie 才能持續存取

**打包檔最早涵蓋到哪一年？**

- 司法院於民國 106 年（2017-03-22）開始釋出，首波為 **105 年度**，以月份分檔
- 新聞稿表示將「逐次公開 104 年、103 年、102 年度等」
- **但是否真的一路補到民國 89 年，無法從外部確認**（資料集清單需登入才看得到）

### 行動項目

1. 註冊 opendata.judicial.gov.tw 帳號（建議以研究專案名義申請，由計畫主持人具名）
2. 登入後確認**最早可下載的年份**
3. 依結果決定研究區間：

   - 研究設計上，**區間短但資料完整**通常優於區間長但前段殘缺

## 5. 實作細節與陷阱

### 5.1 全文不一定是文字

API 的 `JFULLTYPE` 有兩種型態：

- `text` → `JFULLCONTENT` 為文字內容，`JFULLPDF` 為空
- `file` → `JFULLPDF` 為 PDF 下載連結

**必須實作 PDF 文字抽取 fallback。**
否則這批案件會整批消失，且不是隨機消失（附表多、案情複雜的大案更可能是 PDF），
會造成系統性偏誤。

另有 `ATTACHMENTS` 陣列，內含附件 PDF 的 TITLE 與 URL。

### 5.2 判決可能被下架，且有刪除義務

規格明訂：

- 同一 `jid` 再次出現在異動清單 → 內容可能有異動，**應以後取得的覆蓋先前的**
- 若回傳 `{"error":"查無資料，本裁判可能未公開或已從系統移除..."}`
  → 表示已移除或不再公開，**使用者應刪除先前取得的內容**

**→ 資料庫 Day 1 就要有版本與狀態欄位。**

### 5.3 官方欄位嚴重不足，需自行解析

官方只提供：JID、年度、字別、號次、日期、案由（JTITLE）、全文（JFULL）。

**沒有**以下欄位，全部要從 JFULL 解析：

- 當事人 / 被告
- 引用法條
- 審級關聯（原審案號）
- 主文 / 事實 / 理由 的結構切分
- 前科紀錄

已知問題：釋出版本的裁判書結構化程度不足、排版不佳，
存在硬斷行（`\r\n`）、全形空白對齊、純文字表格等雜訊。

### 5.4 審級去重

同一案件的一、二、三審會是三筆不同 jid。
**不去重會嚴重高估案件數。**
需從全文中解析原審案號來串接審級關係。

## 6. 公開範圍的系統性缺口（須寫入研究限制）

公開裁判書 ≠ 全部犯罪案件。母體僅代表「有進入司法程序、依法公開、且目前仍公開的裁判」。

| 缺口 | 影響 |
|---|---|
| **性侵害案件依法不公開** | Crime-first 的 sexual violence 分支整段消失；國外文獻中動物虐待與性暴力關聯是重要一塊 |
| **少年事件不公開** | 影響最大。「童年／少年虐待動物 → 成年暴力犯罪」是理論最核心環節，但完全不在公開資料中 |
| **不起訴處分書不在裁判書系統** | 「動保案件沒成案」的案件正好落在這裡，撈不到 |
| 未報案 / 僅社政通報 / 未被發現 | 完全不在母體內 |

### 6.1 法規變動造成的趨勢假象（重要）

動物保護法的刑責規定隨時間多次修訂並加重。
同樣行為在不同年代有不同的成案機率與判決書產出量。

**→ 直接畫 2000–2026 的動物虐待案件數趨勢線會看到上升，但那可能是修法、社會關注度、
通報意願造成的，不是行為本身變多。**

建議在分析設計階段就把法規變動時間點當成控制變項或斷點，而非事後補說明。
趨勢圖最容易被外界拿去下錯結論，對外呈現時特別危險。

## 7. 資料架構

### 7.1 整體流程

```
          司法院裁判書 Open Data（月打包 + API 增量）
                        │
                        ▼
              Layer 1：全量刑事裁判 Raw DB
                        │
           ┌────────────┴────────────┐
           ▼                         ▼
     Animal-first               Crime-first
   動物詞 + 暴力詞命中        重大犯罪案由 → 全文查動物線索
           │                         │
           └────────────┬────────────┘
                        ▼
              Layer 2：Candidate Pool（寬鬆召回）
                        │
              Layer 3：NLP / Rule extraction
                        │
                        ▼
                  Event Database
                        │
              Layer 4：判決內前科序列抽取
                        │
                        ▼
              共現分析 / 時序分析 / 風險分析
```

### 7.2 兩條檢索入口

**Animal-first**

```
所有刑事裁判
  ↓ 動物相關詞命中
狗 / 犬 / 貓 / 寵物 / 動物 / 流浪犬 / 家畜 ...
  ↓ 暴力行為詞命中
殺 / 打 / 踢 / 摔 / 毒 / 勒 / 刺 / 射 / 虐待 ...
  ↓
候選「動物虐待事件」
```

**Crime-first**

```
殺人 / 傷害 / 強盜 / 搶奪 / 家暴 / 恐嚇 /
公共危險 / 毒品 / 竊盜 / 性暴力 ...
  ↓ 全文檢查
動物虐待 / 傷害動物 / 威脅傷害寵物 ...
```

Crime-first 的價值在於捕捉這類案件：

> 「被告持刀威脅妻子，並將家中飼養犬隻殺死」

最後起訴／判決可能只有恐嚇、傷害、家暴，**完全沒有動保法案由**。
這批可能是本研究最有價值的資料。

### 7.3 Layer 3 需區分的情境（降低雜訊）

必須排除的偽陽性：

- 交通事故撞到動物（過失）
- 獸醫醫療糾紛
- 動物造成他人受傷
- 動物保護行政事件
- 比喻用語（如「像畜生一樣」）
- 合法宰殺（畜牧、狩獵）

要保留的：

- 人為故意虐待
- 威脅傷害動物（作為控制手段）

### 7.4 資料表設計

```text
judgments_raw
  jid              -- primary key, e.g. "CHDM,100,訴,1552,20130517,2"
  court            -- parsed from JID prefix
  case_type        -- V/M/A/P/C, parsed from JID
  jyear
  jcase
  jno
  jdate
  jtitle           -- 案由
  jfull            -- full text
  jfull_type       -- text | file
  jfull_pdf_url
  attachments      -- json array
  source           -- bulk_package | api
  downloaded_at
  last_checked_at
  is_public        -- for takedown compliance
  version
```

```text
judgments_processed
  jid

  -- animal related
  animal_mentioned
  animal_type
  animal_abuse
  animal_abuse_type
  animal_killed
  animal_injured
  animal_threatened

  -- human crime flags
  domestic_violence
  human_injury
  homicide
  robbery
  theft
  drug
  public_danger
  sexual_violence
  threat

  -- case facts
  offense_date
  defendant
  victim
  relationship

  -- audit
  animal_abuse_evidence   -- REQUIRED: original text snippet
  confidence
```

```text
prior_convictions        -- extracted from within each judgment
  jid                    -- source judgment
  defendant_ref          -- defendant identifier within this judgment only
  prior_offense
  prior_court
  prior_sentence
  prior_final_date
  prior_completed_date
  evidence_text
```

### 7.5 evidence 欄位為強制要求

當模型判斷 `animal_abuse = TRUE`，旁邊必須保留原文，例如：

> 「……持棍棒毆打其所飼養之犬隻……」

目的：研究助理可快速人工確認，不需重讀整篇判決。

## 8. 舊資料的角色

既有資料：

- `89-111年動保民事判決(0626完).docx` — 民事，性質與刑事分析路線不同，需先確認內容
- `全國裁判書整理資料_V1.xlsx` — 約 1,500 筆 + 500 多筆
- 由湘敏於約四年前撈取

**決定：不作為母體，改作 Gold Set / Validation Set。**

用途：驗證新 pipeline 的 recall。例如舊資料有 1,500 件已知動保案件，
新系統找到 1,420 件 → Recall 94.7%，再去研究漏掉的 80 件有何共同特徵。

可能發現：判決未使用「虐殺」，而寫成「以不當方式致動物死亡」
→ 將此語言加入 retrieval rule → 重跑提升至 99%。

這比直接沿用舊資料科學得多。

> ⚠️ 尚未取得這兩份檔案的實際欄位，需補齊後才能設計對照邏輯。

## 9. 控制組 / 背景母體

若要回答「動物虐待是不是犯罪升級的風險訊號」，需要 denominator：

|  | 後續重大暴力犯罪 Yes | No |
|---|---|---|
| 其他犯罪 + 動物虐待 | 120 | 880 |
| 其他犯罪、無動物虐待 | 400 | 9,600 |

沒有控制組，結論只會是「虐待動物的人裡面有很多後來犯罪」，存在嚴重 selection bias。

**注意**：動物虐待在判決中嚴重低度記載，「未提及動物虐待」≠「沒有動物虐待」，
此 misclassification 會稀釋效果量，須寫入限制。

若算力不足，可改用抽樣控制組（例如隨機抽 10 萬筆刑案）。

## 10. 基礎設施需求

已知量體參考：全部判決書資料檔壓縮約 **34GB**，解壓後約 **112GB**。
社群經驗指出以一般程式處理相當吃力。

因此：

- ❌ 不能用 Excel，不建議 pandas 直接硬讀
- ✅ 全文檢索引擎（Elasticsearch / OpenSearch）或欄式儲存（DuckDB + Parquet）
- ✅ LLM extraction **絕不能對全量跑**，必須是漏斗：
  `正則／關鍵字粗篩 → 縮到數萬筆 → 才進 LLM`

Layer 2 原則：寧可「撈 50,000 筆 → 最後剩 5,000」，
也不要「搜尋太精準 → 撈 2,000 → 漏掉另外 3,000」。

## 11. 執行順序建議

不要一次做全年份。

### Phase 0：可行性確認
- 註冊帳號，確認最早可下載年份
- 取得舊資料（docx / xlsx）確認欄位
- 確認家暴通報統計數字出處

### Phase 1：Pilot（建議 3 個年份，挑修法前後各一段）
完整跑一次 Layer 1–3，目的不是產出研究結果，而是驗證：
- 撈取規則的 recall（用舊 1,500 筆當 Gold Set）
- 雜訊率
- 單位成本（時間 / 金額 / 人工複核人天）

### Phase 2：全量擴張
Pilot 過關後才做，此時已能做出可信的專案計畫。

### Phase 3：控制組與背景母體
成本最高，等分類器準確率確認後再投入。
否則等於用不穩定的分類器去標註百萬筆資料。

### Phase 4：增量維護
用官方 API 做夜間排程更新。
